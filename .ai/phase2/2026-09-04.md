Core `rc.31` is rejected for this spike because the current theme and official ecosystem plugins still require core `rc.30` exactly. The client is also a direct dependency because site components import its composables; declaring it at the root prevents duplicate physical client instances and injection-key mismatches. All direct RC dependencies are exact versions. Vite, Vue, Vue Router, and `@vitejs/plugin-vue` remain owned by the selected bundler and will be locked to the concrete versions resolved by npm.

## Plugin migration design

- Remove `vuepress-vite`; install VuePress core, Vite bundler, and default theme explicitly.
- Remove the two `@snippetors` plugins. The default theme already enables the official copy-code and markdown-tab plugins.
- Preserve the existing `:::: tabs` / `::: tab` article source with a local Markdown preprocessor that converts only that legacy container grammar to the official plugin's `:::: tabs` / `@tab` grammar before parsing. Rendering and client behavior remain owned by the official plugin.
- Replace `vuepress-plugin-md-enhance` with `@vuepress/plugin-markdown-math` configured for MathJax and install the exact current `@mathjax/src` renderer.
- Install Dart Sass directly to satisfy the default theme and Vite optional peer ranges. `sass-loader` and `sass-embedded` are not required by the Vite bundler and remain uninstalled.
- Keep production Shiki and development Prism behavior for this phase, then verify both paths.

## Validation results

### Installation and dependency tree

Validation used the exact Phase 1 runtime rather than the machine default:

```text
Node 22.18.0
npm 10.9.3
```

- A clean `npm ci` completed successfully and installed 539 packages.
- `npm ls --depth=0` completed without `invalid` or `extraneous` entries.
- A targeted `npm ls` confirmed one VuePress core/client line at `2.0.0-rc.30`, Vue `3.5.42`, Vue Router `5.3.1`, Vite `8.2.2`, and `@vitejs/plugin-vue 6.0.8`.
- Only one physical `node_modules/@vuepress/client/package.json` exists. This matters because separate client instances use separate injection keys and caused `useClientData() is called without provider` during the migration spike.
- The direct RC dependencies in `package.json` are exact; npm owns the compatible transitive Vite/Vue versions through the lockfile.

### Migration findings

- The default theme home alias changed from `@theme/Home.vue` to `@theme/VPHome.vue`. Updating the alias restored the existing custom homepage; leaving the old alias silently rendered the default VuePress home.
- `LeetCode.vue` and the custom home now import client composables from the single direct `@vuepress/client` dependency. This removes the duplicate-provider SSR/runtime fault observed during the spike.
- The two snippetors plugins were replaced by the default theme's official copy-code and markdown-tab plugins. A narrow local Markdown preprocessor converts the repository's existing tab container grammar before parsing, so all 43 article tab groups render without modifying article Markdown.
- `vuepress-plugin-md-enhance` was replaced by the official markdown-math plugin and MathJax 4. Formula rendering was found on 16 generated pages.
- A clean install with the upstream, unpatched `@babel/runtime@7.20.13` built successfully. The obsolete patch, `patch-package`, and `postinstall` hook were therefore removed rather than moved to a newer runtime.
- The official tab renderer exposes all notebook iframe references during SSR. The local link verifier now exempts the complete `/static/jupyter/` prefix because those files are produced and merged by the separately accepted `website-binder` deployment job; it does not claim that the existing 16 missing local notebook outputs were fixed.

## Residual risks

- VuePress remains in RC. The current theme/plugin releases peer exactly to core `rc.30`, while core `rc.31` is already published. Keep this matrix pinned and reassess the whole matrix together; do not upgrade core alone.
- The custom home contains a `<body>` element nested under the theme's `<main>`. Vite reports this invalid HTML in development and both localized homepages retain the already accepted hydration mismatch. This is an existing issue, not a Phase 2 regression, and must be reconsidered after the full dependency upgrade as agreed.
- Bootstrap 4 Sass emits extensive deprecation warnings under Dart Sass 1.104. Phase 3 already plans to replace its limited use with local CSS and remove Bootstrap.
- Rolldown reports the existing `eval` in `Lang.vue`; Phase 4 already owns removing remote script evaluation. The Lang chunk also grew from about 628 KiB to 756 KiB and should be bundle-analyzed there.
- BIM remains about 1.25 MiB and the general chunk-size warning remains. No business dependency was upgraded or split in this phase.
- The two pages without sidebar configuration and the 16 notebook outputs absent from a docs-only build remain accepted baseline issues.
- The install audit reported 20 dependency vulnerabilities (1 low, 6 moderate, 11 high, 2 critical). No automatic audit fix was applied because it would expand this compatibility spike into uncontrolled business-dependency upgrades; security remediation belongs in a separately reviewed phase.
- The internal-reference count changed from the Phase 1 baseline because the new theme/plugin SSR markup differs and deployment-provided notebook references are now treated by prefix. Route and critical-artifact checks remain exact, and browser verification covered the affected rendering paths.
