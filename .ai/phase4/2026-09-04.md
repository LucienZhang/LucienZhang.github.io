## 远程数据安全

### TIOBE

`Lang.vue` 不再从代理响应中提取 JavaScript 后交给 `eval`。新的 `tiobe-parser.mjs` 只接受以下有限语法：

- series 必须是 `{ name: '...', data: [...] }`；
- 每个数据点必须是 `[Date.UTC(year, month, day), number]`；
- 文档、series 数量、单 series 数据点数量和名称长度均有上限；
- 任何剩余表达式、函数调用或不支持的转义都会使整个解析失败。

TIOBE 表头也不再通过 `v-html` 注入。解析器只输出纯文本、受限 `colspan`、本地图标 basename 和排名字段；远程 `style` 等属性不会进入 DOM。语言详情链接固定在 `https://www.tiobe.com/tiobe-index/` 下，并以 `noopener,noreferrer` 打开。

2026-09-04 下载的 TIOBE 官方页面样本可被解析为 10 条 series（第一条 299 个数据点）和 20 行排名。自动安全 fixture 另外证明带赋值表达式的伪造 series 会被拒绝，远程表头中的 `onerror` 不会进入解析结果，也不会执行。

### LeetCode

LeetCode 响应只按 JSON 解析；排名和积分必须转为有限整数，历史记录最多保留 1,000 条，比赛标题截断为 200 字符。NVD3 tooltip 在拼接 HTML 前会转义所有第三方文本和数值，避免比赛标题成为 HTML 注入入口。NVD3 样式已随站点本地提供，不再依赖 cdnjs。

### Pseudo 与其他静态资源

`Pseudo.vue` 不再运行时导入 jsDelivr 上的 MathJax 3，而是动态加载项目已经固定的 `@mathjax/src 4.1.3` 的 `tex-svg` bundle；MathJax loader 根路径固定为本站，伪代码 CSS 也移除了远程 KaTeX import。浏览器 smoke 会拒绝任何 jsDelivr/cdnjs 请求，并要求页面实际生成 MathJax SVG。MathJax 4 官方文档确认 `@mathjax/src` 包含可自托管的 bundle，同时说明 v4 字体与 v3 的路径模型不同：[Hosting Your Own Copy of MathJax](https://docs.mathjax.org/en/latest/web/hosting.html)、[Loading MathJax](https://docs.mathjax.org/en/latest/web/loading.html)。加载失败会显示可重试状态。Binder badge 加载失败时退化为文本链接。

主页已有的 Google Fonts fallback 和文章中的 Replit sandbox iframe 不属于本阶段的主动数据集成：前者留给 Phase 5 视觉与字体策略，后者是显式、lazy、带 sandbox 的文章嵌入，失败不会造成站点 loading 状态。它们未被本阶段扩大修改。

## CORS proxy 边界审计

前端不再允许组件构造任意 proxy 请求。`remote-data.mjs` 只导出四个业务函数，URL、方法、GraphQL operation、变量、可转发 header 都固定为：

| 目标 | 方法 | 前端允许内容 |
| --- | --- | --- |
| TIOBE index | GET | 无自定义 header、cookie 或 body |
| LeetCode profile | GET | 无自定义 header、cookie 或 body |
| LeetCode global GraphQL | POST | 固定 referer/content-type、固定 query/username、上一步返回的 cookie |
| LeetCode CN GraphQL | POST | 固定 content-type、固定 query/userSlug、无 cookie |

Axios client 统一设置 12 秒 timeout 和 `withCredentials: false`。每个组件用 `AbortController` 取消被重试覆盖或卸载后的请求；两者分别对应 Axios 官方 request config 和 cancellation API：[Request config](https://axios-http.com/docs/req_config)、[Cancellation](https://axios-http.com/docs/cancellation)。

这只收紧了浏览器调用面，不是服务器安全边界。当前仓库不包含 `api.ziliang.ninja` 的实现，因此无法在本站代码中证明后端策略。proxy 后端仍必须独立做到：按 scheme/hostname/port/path 精确 allowlist；拒绝跳转到非 allowlist 目标；按目标限制 GET/POST；重建而非透传 header；只允许 LeetCode profile cookie 流向同站 GraphQL；限制 cookie/body/response 大小与响应时间；解析 DNS 后拒绝 loopback、link-local 和私网地址。部署前应在后端仓库逐项复核，不能依赖前端模块阻止 SSRF 或任意转发。

## PR review follow-up — 2026-09-05

PR #8 的自动 review 指出：D3 或 NVD3 动态导入失败时，`assetsReady` 保持为 `false`，但错误态 Retry 直接调用 `loadData()`，会被其前置检查立即返回。修复后所有 Retry 都进入统一的 `retry()`：资源已就绪时只重试数据，否则重新执行资源初始化。每次初始化使用不同的本地 query key，避免浏览器复用一次失败的 module fetch。

浏览器 smoke 增加了对应回归：首次导航 LeetCode 页面时同时屏蔽 D3/NVD3 和 API，确认出现错误态；随后只解除本地资源屏蔽、点击 Retry，并要求 `window.d3` 与 `window.nv` 成功出现。API 继续保持屏蔽，因此资源恢复后还会验证数据层仍能独立收敛到可重试失败态。

同一轮 PR review 还指出，同源 notebook URL 返回 404 时 iframe 仍会触发 `load`，原实现仅凭 `documentElement` 存在就会误报成功。Jupyter 组件现在先用同源 `HEAD` 请求验证 HTTP 状态与 HTML content type，通过后才挂载 iframe；Retry 会重新执行该验证。浏览器 smoke 先让 notebook 请求返回 404 并确认错误态，再启用测试 notebook、点击 Retry，并确认 iframe 加载了预期内容。

现有两个中文 projects sidebar warning 和大 chunk warning 仍存在，均为升级前已接受事项。docs-only 构建不包含部署 workflow 从 `website-binder` 合并的 notebook HTML，因此 Jupyter 的最终内容仍需在 Pages artifact/线上验证；本阶段只验证组件和 iframe 生命周期。
